# Changelog — Tessera v1 (`dev/v1` branch)

Experimental hotfix branch cut from `main`. Changes here are **NOT** part of a
release or the distribution tarball yet — this branch is for testing breaking
changes before they are promoted.

**Rule:** an entry is appended immediately after the corresponding change is
implemented **and** verified (local build / smoke test / `systemd-analyze`).

## [Unreleased] — dev/v1

### Added
- **`CHANGELOG.md`** (this file) — documents every change on `dev/v1`.
- **Canonical-prefix repo model.** `tessera repo init` (no args) now
  initializes at `~/.local/share/tessera` (matches `install.sh`
  `TESSERA_PREFIX`) instead of cwd. Constants `DEFAULT_PREFIX` and
  `ROOT_MARKER` (`.tessera-root`) added to `repo.py`.
- **Root marker.** `write_root_marker()` writes
  `~/.local/share/tessera/.tessera-root` (presence = canonical root; contents
  record the resolved absolute path for readability).
- **`tessera runtime enable`** command — writes + enables the systemd unit
  without re-initializing the repo (thin companion to `repo init`).
- **`tessera_runtime/systemd_units.py`** — generates the non-template
  `tessera-runtime.service`, hardcodes the absolute `WorkingDirectory=` and
  `TESSERA_REPO=`, and starts the runtime via systemd (with `is-active`
  verification) or falls back to a detached direct daemon.
- **`tessera_runtime/daemon.py`** — extracted the detached-daemon launcher
  (previously inline in `cli.runtime_start`) so `runtime start` and `repo
  init`'s post-init hook share one implementation.

### Changed
- **Discovery order (`get_repo_root`).** Now cwd-walk first (wins when you
  are standing inside a repo), then the canonical marker as a *fallback*
  when not in any repo. Earlier draft preferred the marker globally, which
  broke local repos and the test suite — corrected before merge.
- **`tessera repo init`** now: inits dirs → writes marker → starts the
  runtime (systemd when available, else direct), printing each step.
- **systemd unit is now non-template** `tessera-runtime.service` (was
  `tessera-runtime@.service`). `WorkingDirectory=`/`-repo` are hardcoded to
  the absolute canonical path. `ExecStart`/`ExecStop` are double-quoted so
  binaries with spaces in their path (e.g. a space-containing workspace) do
  not trigger systemd `203/EXEC`.
- **`install.sh` (`02-scaffold.sh`)** no longer emits a systemd unit; the
  unit is generated by `tessera repo init` / `tessera runtime enable`.

### Fixed
- **`dev/v1` systemd unit `%f` / absolute-path bug.** The previous
  `tessera-runtime@.service` used `%I` for `WorkingDirectory`, which of a
  `systemd-escape --path` instance is a *relative* path → "WorkingDirectory=
  path is not absolute". Replaced with the non-template unit that hardcodes
  the resolved absolute path (verified with `systemctl --user is-active`
  → `active`).
- **False start success.** `start_runtime()` now checks `systemctl --user
  is-active` and falls back to a direct daemon when the unit is not active
  (previously reported success on `enable --now` returncode alone).

### Verification
- `pytest tests/` → **164 passed** (was 164; 7 transient failures during
  development were caused by a leaked marker from manual testing + the
  marker-global discovery order, both fixed).
- `e2e/smoke_test.py` → **PASSED**.
- Manual end-to-end (space-free install like production):
  - `tessera repo init` → dirs + marker + `tessera-runtime.service`
    (absolute, quoted) → `systemctl --user enable --now` → **active**;
    `runtime status` → `running: yes`; `runtime stop` → clean.
  - Local repo (`tessera repo init /tmp/x`) wins via cwd-walk over the
    canonical marker (no regression for non-prefix repos).
  - Idempotent re-init reports "already initialized" and re-writes unit.
- Direct-daemon fallback verified on a host without a usable systemd user
  session (socket comes up, `runtime status` = running).

### Notes / Risks
- Single canonical repo model intentionally collapses the old per-repo
  multi-instance design. Multi-repo workflows are out of scope on this
  branch; local repos still work via cwd-walk.
- The systemd path requires a space-free `tessera` binary. Production
  installs use the `~/.local/bin/tessera` symlink (clean path); a developer
  running from a workspace whose path contains spaces will hit `203/EXEC`
  until they install properly — the direct-daemon fallback covers that case.
- `tessera runtime reset` (disable unit + remove marker, keep tickets) is
  deferred (per decision: only `runtime enable` added now).
- This branch is NOT distributed; `02-scaffold.sh`/RFC-0013/INSTALL.md were
  updated to reflect the unit-now-from-`repo init` model for honesty, but the
  release tarball is unchanged until promoted.
