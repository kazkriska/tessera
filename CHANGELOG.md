# Changelog — Tessera v1 (`dev/v1` branch)

Experimental hotfix branch cut from `main`. Changes here are **NOT** part of a
release or the distribution tarball yet — this branch is for testing breaking
changes before they are promoted.

**Rule:** an entry is appended immediately after the corresponding change is
implemented **and** verified (local build / smoke test / `systemd-analyze`).

## [Unreleased] — dev/v1

### Added
- **`CHANGELOG.md`** (this file) — documents every change on `dev/v1`.
- **Canonical-prefix repo model.** `tessera repo init` (no args) now
  initializes at `~/.local/share/tessera` (matches `install.sh`
  `TESSERA_PREFIX`) instead of cwd. Constants `DEFAULT_PREFIX` and
  `ROOT_MARKER` (`.tessera-root`) added to `repo.py`.
- **Root marker.** `write_root_marker()` writes
  `~/.local/share/tessera/.tessera-root` (presence = canonical root; contents
  record the resolved absolute path for readability).
- **`tessera runtime enable`** command — writes + enables the systemd unit
  without re-initializing the repo (thin companion to `repo init`).
- **`tessera runtime completion install`** — writes the zsh completion script
  to `~/.local/share/tessera/zfunc/_tessera` (not `~/.zfunc` in `$HOME`),
  keeping all Tessera state under the prefix. Wired into `02-scaffold.sh`.
- **`tessera repo clean`** — removes a stray `~/.ticket-runtime/` left by
  pre-dev/v1 usage (refuses if a runtime looks live there).
- **`tessera_runtime/systemd_units.py`** — generates the non-template
  `tessera-runtime.service`, hardcodes the absolute `WorkingDirectory=` and
  `TESSERA_REPO=`, and starts the runtime via systemd (with `is-active`
  verification) or falls back to a detached direct daemon.
- **`tessera_runtime/daemon.py`** — extracted the detached-daemon launcher
  (previously inline in `cli.runtime_start`) so `runtime start` and `repo
  init`'s post-init hook share one implementation.
- **`tessera_runtime/socket_location.py`** — relocates the runtime socket to
  `$XDG_RUNTIME_DIR/tessera/<repo-hash>/runtime.sock` (see "Fixed" below).

### Changed
- **Discovery order (`get_repo_root`).** cwd-walk first (wins when you are
  standing inside a repo), then the canonical marker as a *fallback* when not
  in any repo.
- **`tessera repo init`** now: inits dirs → writes marker → starts the
  runtime (systemd when available, else direct), printing each step.
- **systemd unit is now non-template** `tessera-runtime.service` (was
  `tessera-runtime@.service`). `WorkingDirectory=`/`-repo` are hardcoded to
  the absolute canonical path. `ExecStart`/`ExecStop` are double-quoted so
  binaries with spaces in their path don't trigger `203/EXEC`.
- **`install.sh` (`02-scaffold.sh`)** no longer emits a systemd unit; the
  unit is generated by `tessera repo init` / `tessera runtime enable`. It now
  also installs the zsh completion under the prefix.

### Fixed
- **Stray runtime state at `$HOME` (the `~/.ticket-runtime/runtime.sock` bug).**
  Root cause was two-fold: (a) `runtime_socket_path()` built
  `<root>/.ticket-runtime/runtime.sock` — dropping `TicketsRepository` — so a
  `repo init`/`runtime start` from `~` created `~/.ticket-runtime/`; and (b)
  a Unix domain socket path is capped at ~107 bytes, so the *correct*
  `<root>/TicketsRepository/.ticket-runtime/runtime.sock` `bind()` fails with
  `OSError: AF_UNIX path too long` for any but the shallowest repos — which is
  exactly why state got scattered. Fix: the socket now lives at
  `$XDG_RUNTIME_DIR/tessera/<repo-hash>/runtime.sock` (short, ephemeral per
  Invariant I-2, per-repo via a stable path hash), always within the OS
  limit. Durable state (`registry.db`, logs, locks) stays in
  `<repo>/TicketsRepository/.ticket-runtime/` per CONTRACTS §7.1.
- **`repo_init` guard** refuses to bootstrap a runtime tree directly under
  `$HOME` (or `$HOME/.ticket-runtime`), so `~/.ticket-runtime` can never be
  re-created.
- **SDK `Runtime.connect`** now learns the repo root from the server's
  `status` RPC (the socket path no longer encodes the repo root).
- **`dev/v1` systemd unit `%f` / absolute-path bug** (prior session) — the
  non-template unit hardcodes the resolved absolute path; verified
  `systemctl --user is-active` → `active`.
- **False start success.** `start_runtime()` checks `systemctl --user
  is-active` and falls back to a direct daemon when the unit is not active.

### Verification
- `pytest tests/` → **164 passed** (regressed to 11 failures mid-change when
  the socket path exceeded AF_UNIX limit; fixed by the XDG_RUNTIME_DIR move).
- `e2e/smoke_test.py` → **PASSED** (stable across repeated runs).
- Manual end-to-end (space-free, production-like install):
  - `tessera repo init` → dirs + marker + `tessera-runtime.service`
    (absolute, quoted) → `systemctl --user enable --now` → **active**;
    `runtime status` → `running: yes`, socket at
    `/run/user/<uid>/tessera/<hash>/runtime.sock` (53 bytes, under limit).
  - `tessera repo init ~` → clean error, no `~/.ticket-runtime` created.
  - `tessera completion install` → writes `_tessera` under the prefix
    zfunc; does NOT touch `~/.zfunc`.
  - `tessera repo clean` → removes a stray `~/.ticket-runtime`.
  - No `~/.ticket-runtime`, no stray socket under `$HOME` at any point.

### Notes / Risks
- Single canonical repo model intentionally collapses the old per-repo
  multi-instance design. Local repos still work via cwd-walk.
- The systemd path requires a space-free `tessera` binary (production uses
  the `~/.local/bin/tessera` symlink). The direct-daemon fallback covers
  space-containing dev paths.
- `tessera runtime reset` (disable unit + remove marker, keep tickets) is
  still deferred.
- CONTRACTS.md §7.1 still says the socket is under `.ticket-runtime/`; that
  doc should be updated to reflect the XDG_RUNTIME_DIR socket location
  (tracked, not yet edited on this branch).
- This branch is NOT distributed; `02-scaffold.sh`/RFC-0013/INSTALL.md were
  updated for honesty, but the release tarball is unchanged until promoted.

### Changed (this change set: scattered-home-state fixes)
- **`runtime_socket_path`** moved to `socket_location.py`: socket now under
  `$XDG_RUNTIME_DIR/tessera/<repo-hash>/runtime.sock` (fixes the
  `~/.ticket-runtime/runtime.sock` stray-state bug + AF_UNIX length limit).
- **`repo_init` guard** against `$HOME`/`<home>/.ticket-runtime` roots.
- **`tessera repo clean`** removes a stray `~/.ticket-runtime`.
- **`tessera completion install`** + `02-scaffold.sh` install the zsh
  completion under the prefix (`~/.local/share/tessera/zfunc/_tessera`)
  instead of `~/.zfunc`. INSTALL.md uninstall updated accordingly.
