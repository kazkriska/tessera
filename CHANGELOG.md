# Changelog — Tessera v1 (`dev/v1` branch)

Experimental hotfix branch cut from `main`. Changes here are **NOT** part of a
release or the distribution tarball yet — this branch is for testing breaking
changes before they are promoted.

**Format:** governed by `formal-specifications/rfcs/rfc-0014-changelog-standard.md`.
Change entries are a single numbered list in ascending chronological order; each
entry carries a `[YYYY-MM-DD HH:MM UTC]` timestamp (date only when no time is
recoverable), a category, and the commit that implemented it. Notes and risks are
footnotes linked to entries by list position. Entry numbers are stable
identifiers — new entries are appended, never renumbered.

**Append rule:** an entry is appended immediately after the corresponding change
is implemented **and** verified (local build / test suite / smoke test).

### Notes & risks

[^1]: *Applies to entries 2, 3, 7, 27.* The single canonical repo model intentionally collapses the old per-repo multi-instance design; local repos still work via cwd-walk. The marker is a **default location, not an override** — a leftover marker from manual testing silently poisons the next test run, so clean `~/.local/share/tessera` after manual `repo init` verification.
[^2]: *Applies to entries 5, 9, 12.* The systemd path requires a space-free `tessera` binary — production uses the `~/.local/bin/tessera` symlink. A space-containing developer path triggers `203/EXEC`; the direct-daemon fallback covers that case. `systemctl --user enable --now` returns 0 even when the unit subsequently fails, which is why `is-active` is checked explicitly.
[^3]: *Applies to entry 7.* An earlier draft preferred the marker **globally**, which broke local repos, 7 unit tests and the e2e run — every command resolved to the leaked prefix marker. Corrected before merge.
[^4]: *Applies to entries 10, 20.* This branch is **not distributed**. `02-scaffold.sh`, RFC-0013 and `INSTALL.md` were updated for honesty, but the release tarball is unchanged until `dev/v1` is promoted.
[^5]: *Applies to entries 13, 16, 18, 26.* A Unix domain socket path is capped at ~107 bytes, so the *correct* `<repo>/TicketsRepository/.ticket-runtime/runtime.sock` fails `bind()` with `OSError: AF_UNIX path too long` for any but the shallowest repos — which is exactly how state got scattered to `$HOME`. The `$XDG_RUNTIME_DIR` location is short (~50–55 bytes), ephemeral per Invariant I-2, and per-repo via a stable path hash. Durable state stays in `.ticket-runtime/`.
[^6]: *Applies to entries 15, 20, 22.* zsh scans each `fpath` entry **flat and non-recursively** for a `_<cmd>` file, so writing the completion file alone does nothing — the directory must be on `fpath`. Activation requires `source ~/.zshrc` or a new shell.
[^7]: *Applies to entry 19.* **Corrects a stale claim.** The pre-reconstruction changelog stated that `CONTRACTS.md` §7.1 "still says the socket is under `.ticket-runtime/`" and was "not yet edited on this branch". That was already false when written: commit `a84179f` updated §7.1 in the same change set. Verified against the current tree at `CONTRACTS.md:215`.
[^8]: *Applies to entries 21, 23.* `TicketsRepository/.gitkeep` was restored and then removed again 23 minutes later. **Current state:** `TicketsRepository/` is absent from the working tree and nothing is tracked under it; `tessera repo init` recreates it. Risk: the empty tracked directory no longer survives a fresh clone.
[^9]: *Applies to entry 24.* `runtime reset` **preserves tickets and `registry.db`** — only the daemon wiring is undone. It defaults to `DEFAULT_PREFIX` (where `repo init` installs the daemon) rather than cwd-walk, so a plain `reset` cannot accidentally target an unrelated local repo. Prompts for confirmation unless `--yes`.
